# Design Guardrails

The rules the drift check enforces and the engine reasons about. Keep them
specific and checkable. When drift keeps violating a rule, the engine proposes a
tighter guardrail here as a HITL card — guardrails are never self-modified silently.

## Tokens

- All color, spacing, radius, and type values reference tokens in
  `design/tokens.css`. No raw hex (`#rrggbb`), no raw `rgb()/hsl()`, no magic
  pixel values in component code.
- New tokens are added to `design/tokens.css` first, then referenced — never
  inlined "just this once".

## Spacing & layout

- Spacing uses the token scale (multiples of `--space-base`). No arbitrary px gaps.
- Prefer layout primitives over one-off margins.

## Type

- Font sizes, weights, and line-heights come from the type tokens. No ad-hoc sizes.

## Accessibility

- Text/background pairs meet WCAG AA contrast (4.5:1 body, 3:1 large text).
- Interactive targets are at least 44×44px; every control has an accessible name.

## Components

- A component variant is added only with a stated reason (link the experiment in
  `experiments/`). Unused variants are pruned.

## No AI slop

The rules that keep a fast-shipping agent from turning the UI into a pile of
one-offs. These are the anti-slop guardrails — the reason this file exists.

- **One component per concept.** There is exactly one Button, one Card, one Modal.
  If one exists, reuse it — never rebuild a primitive inline in a screen.
- **No mixed component libraries.** Pick one source (e.g. shadcn) and stay in it.
  Don't introduce a second UI kit alongside it.
- **Screens compose, they don't re-implement.** A page imports shared components;
  it doesn't hand-roll its own buttons, inputs, or cards.
- **Consistent variant vocabulary.** The same concept is spelled the same way
  everywhere (`variant="primary"`, not `type="main"` in one place and `isPrimary`
  in another).
- **New pattern → ask first.** If a screen needs something the system doesn't have
  yet, propose the component or token with a rationale and wait — don't invent a
  local variant to move faster.

## Autonomy

How strictly these rules are enforced follows the **autonomy dial** in
`systemix.config.yaml` (ghost / assisted / autonomous). At every level, **changing
this file is always human-in-the-loop** — the engine proposes a tighter or looser
guardrail as a HITL card and never edits the rules silently. Customise the rules
here to fit your product; the agent reads whatever you keep in this file.
